## 3. Strict Constraints & Boundaries
- **Scope Limitation:** ONLY modify the files explicitly listed above. Do not touch or refactor unrelated code.

- **Theme Consistency:** Follow the existing project structure, naming conventions, and UI design themes (CSS classes, color schemes, component structures).

## 4. Anti-Hallucination & Execution Guidelines
To ensure a successful and direct implementation, adhere to the following rules:
- **No Unprompted Enhancements:** Do not add "extra" features, Easter eggs, or unsolicited refactoring. Implement ONLY what is requested.
- **Stop When Done:** Once the required logic is written, terminate your response. Do not get stuck in a loop of self-correction or outputting endless variations of the code.
- **No Dummy Code:** Provide actual, working code. Do not use placeholders like `// Add logic here` unless instructed to do so.
- **Concise Explanations:** Keep explanations brief. Focus primarily on providing the correct code blocks.
